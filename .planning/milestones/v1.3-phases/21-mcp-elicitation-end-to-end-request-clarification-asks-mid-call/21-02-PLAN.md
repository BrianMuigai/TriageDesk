# Phase 21 · Plan 02 — The interrupt round-trip and the ONE respond loop

## Objective

Turn the tool's mid-call question into a real LangGraph `interrupt()`, and let one caller-supplied
policy answer it — proved end-to-end through the shipped adapter, not a stub. Keep the approval gate
distinguishable and every existing caller unchanged.

## DRY / SOLID compliance (iron-clad, `docs/CONVENTIONS.md`)

- **DRY** — the interrupt discriminator has one home (`mcp/elicitation.py`); `graph/nodes.py`,
  `durable.py`, the CLI and the desk import it instead of repeating `"mcp_elicitation"`.
- **DRY** — one interrupt loop (`_drive`) serves `invoke_graph` and `resume_paused`, so the
  pause/resume mechanics are written once.
- **SOLID:S** — `durable` owns the durable lifecycle only; the *policy* (what to answer) is injected.
- **SOLID:O** — `respond` is additive and defaults to today's behaviour; no existing signature breaks.
- **SOLID:D** — the loop depends on the LangGraph `Command`/`__interrupt__` interface, not on which
  node interrupted.
- **ELICIT-05** — the two payload types are discriminated by a declared `type` field, never by
  key-sniffing a free-form dict.

<task type="auto">
  <name>Task 2: Add the ONE respond loop to the durable helper</name>
  <files>src/triagedesk/durable.py</files>
  <action>
    In `src/triagedesk/durable.py`:

    1. Declare `RespondPolicy = Callable[[Mapping[str, Any]], Mapping[str, Any] | None]` and document
       the contract: the policy receives ONE interrupt payload and returns the resume value, or
       `None` to leave the run paused (the caller presents it).
    2. Add `pending_interrupt(snapshot) -> dict[str, Any] | None` — the value of the first pending
       interrupt read from `snapshot.tasks[*].interrupts`, or `None`. One reader, so no caller reaches
       into LangGraph's snapshot shape.
    3. Add `_approval_only(decision) -> RespondPolicy` — the DEFAULT: return `dict(decision)` for a
       payload that is not an elicitation (`mcp.elicitation.is_elicitation(payload)` is False), and
       `None` for one. So the default never answers a question with an approval, and today's
       single-gate graph behaves exactly as before.
    4. Add `_drive(graph, config, result, policy)` — the ONE loop: while `result.get("__interrupt__")`,
       take `dict(result["__interrupt__"][0].value)`, remember the FIRST payload, call the policy; on
       `None` break (leaving the run paused); else `graph.ainvoke(Command(resume=dict(answer)),
       config)`. Returns `(result, first_payload)`.
    5. `invoke_graph(graph, initial, config, decision, *, respond=None)` — `policy = respond or
       _approval_only(decision)`; `result = await graph.ainvoke(initial, config)`; return
       `_drive(...)`. Signature stays compatible: `decision` is still the 4th positional parameter.
    6. `resume_paused(tools, *, thread_id, decision=None, db_path, respond=None)` — keep the
       pending-gate check (raise `DurableError` when nothing is pending, before touching a store);
       `policy = respond or _approval_only(decision)` (raise `DurableError` when both are absent);
       read `pending_interrupt(snapshot)`; `answer = policy(pending)` when a payload is present, else
       `dict(decision)`; if `answer is None` return `dict(snapshot.values)` (still paused); else
       `graph.ainvoke(Command(resume=dict(answer)), config)` and `_drive(...)`.
    7. `resume_thread(..., respond=None)` — forward the policy to `resume_paused`.

    Update the module docstring: the helper now owns the ONE pause/resume loop, and the policy is
    injected so the CLI, the desk and the eval runner answer different payload types without a second
    loop. Import `is_elicitation` from `triagedesk.mcp.elicitation` (no `langchain.mcp` import: the
    CLI path must not emit a beta warning). Extend `__all__` with `RespondPolicy`,
    `pending_interrupt`.
