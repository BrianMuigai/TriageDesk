# Phase 21 · Plan 03 — The surfaces: a question is not a decision

## Objective

Let a nurse answer the mid-call question from the two shipped surfaces — the CLI and the desk — with
a presentation that is unmistakably **not** the approval gate, and with no way to commit from it.

## DRY / SOLID compliance (iron-clad, `docs/CONVENTIONS.md`)

- **DRY** — the `{"responses": ...}` resume value is built only by `mcp/elicitation.py`; the CLI and
  the desk call it, so the wire shape exists once.
- **DRY** — every user-facing string lives in `desk/copy.py`; the new panel's copy is declared there,
  not inline in the renderer.
- **DRY** — the desk resumes through the ONE `durable.resume_thread`; the answer route adds a policy,
  not a second resume mechanism.
- **SOLID:S** — the CLI stays a shell: parsing + one call into `durable`. The desk's new module owns
  only the question panel's markup.
- **SOLID:O** — the approval path is untouched; the elicitation path is an additive branch.
- **SOLID:L** — the desk's `_paused_view` still returns the same view keys for every existing state.
- **ELICIT-08** — the panel's field set is a question form; there is no colour, no decision and no
  queue control, so an answer cannot be mistaken for an approval.
