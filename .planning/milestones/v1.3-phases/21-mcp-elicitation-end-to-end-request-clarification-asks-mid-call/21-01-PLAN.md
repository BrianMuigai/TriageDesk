# Phase 21 · Plan 01 — The ninth owned tool: `request_clarification`

## Objective

Add one narrow, read-only owned tool that asks the human a bounded, data-sourced question **inside**
the tool call, and return a typed four-outcome answer. Grow the owned surface 8 → 9 in a single
atomic change so the allowlist cannot drift.

## DRY / SOLID compliance (iron-clad, `docs/CONVENTIONS.md`)

- **DRY** — the question text has exactly one owner: `core.coverage.question_for`. The tool calls it;
  it never authors a question, and no question literal appears in the server or the tests.
- **DRY** — the elicitation wire vocabulary (interrupt discriminator, request key, answer field
  prefix) is declared once in `mcp/elicitation.py` and imported by the server, the CLI and the desk.
- **DRY** — the question bound is `coverage.MAX_CLARIFICATION_QUESTIONS` (already the classifier's
  bound); the tool does not declare a second number.
- **SOLID:S** — the tool is an adapter over `coverage.question_for` and `ctx.elicit`/the input-required
  round; it holds no policy, no scoring and no store access.
- **SOLID:O** — the surface grows by one tool and one allowlist entry; no existing tool body changes.
- **SOLID:D** — the tool depends on the MCP `Context` interface, not on a transport; both the modern
  multi-round-trip path and the legacy back-channel path are behind one private helper.
- **ELICIT-08** — the contract has no colour, priority, target, queue or approval field, and
  `extra="forbid"`, so an answer cannot become a clinical value.

    Declare `_INPUT_REQUIRED_VERSION = "2026-07-28"` (the first revision whose `tools/call` carries
    elicitation inside an `InputRequiredResult` — pinned, not `LATEST_MODERN_VERSION`).

    Add private helpers, each single-purpose:

    1. `_clarification_questions(candidates) -> list[str]` — iterate the ids in the caller's order,
       skip an id `coverage.question_for` rejects (`KeyError`: not in the closed set), stop at
       `coverage.MAX_CLARIFICATION_QUESTIONS`. No question text is authored here.
    2. `_clarification_form(questions) -> type[BaseModel]` — `pydantic.create_model` with one `str`
       field per question, name `answer_field(i)`, `default=""`, `description=question`; render with
       `render_elicitation_schema` inside the tool (the renderer validates spec-validity and raises
       `TypeError` otherwise).
    3. `_answers(form, content) -> list[str]` — the answers in field order, blanks dropped.
    4. `_outcome_from_responses(responses, form) -> ClarificationAnswer` — cancel anywhere →
       `cancelled`; else decline anywhere → `declined`; else accept → `accepted` with the answers;
       a missing key or a non-dict response → `unavailable` with a reason. No path returns a
       non-empty `answers` for a non-accepted outcome.
    5. `_client_can_elicit(ctx) -> bool` — `False` when `ctx` is `None` or its `client_capabilities`
       cannot be read (no request context), else whether `capabilities.elicitation` is present.
    6. `_ask(...)` — the ONE transport branch: when `ctx.protocol_version` is at least
       `_INPUT_REQUIRED_VERSION` use the multi-round-trip path (return an `InputRequiredResult`
       carrying ONE form request keyed `CLARIFICATION_REQUEST_KEY` on the first round; read
       `ctx.input_responses` on the retry); otherwise use the legacy back-channel
       `await ctx.elicit(message, form)` and map `AcceptedElicitation`/`DeclinedElicitation`/
       `CancelledElicitation`. A `NoBackChannelError` or an `MCPError` whose `code` is
       `MISSING_REQUIRED_CLIENT_CAPABILITY` maps to `unavailable`; **any other exception
       propagates** (a transport failure is never swallowed as a clinical answer).

    Then register, after `plan_next_step` and before `commit_priority`:

    ```python
    @server.tool()
    @audited()
    async def request_clarification(
        candidates: list[str], ctx: Context | None = None
    ) -> ClarificationAnswer | InputRequiredResult
    ```

    Body: derive the questions; if none, return `ClarificationAnswer(outcome=UNAVAILABLE,
    reason="no candidate id names a declared discriminator; nothing to ask")`; if the client cannot
    elicit, return `unavailable` with the reason; else `_ask(...)`.

    The docstring must state: the ninth tool, read-only (no store, no queue row, no approval token,
    no colour — ELICIT-01/08); questions come only from `core.coverage.question_for` and a caller
    supplies ids, never text (ELICIT-06); at most three; the four outcomes and the rule that a
    refusal is not a clinical answer (ELICIT-03); an answer is an observation that never advances the
    case past the gate (ELICIT-08); the modern path returns an `InputRequiredResult` because the
    2026-07-28 transport forbids a server-initiated request, and the legacy path uses `ctx.elicit`.
    Update the module docstring's "eight triage tools" to "nine triage tools" and name the two
    unwired tools. Do **not** edit `core/scorer.py`, `core/citations.py` or `audited`.
