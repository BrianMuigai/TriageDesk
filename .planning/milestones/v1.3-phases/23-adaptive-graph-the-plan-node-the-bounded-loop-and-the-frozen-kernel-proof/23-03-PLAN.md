# Plan 23-03 — Every decision is a durable, replayable fact

## Objective

Make the "why next?" record real: the planner decision is a typed contract in the audit trail
*and* a structural fact on the local span stream, so a reviewer can replay one adaptive run and
see what was decided, at which step, and whether the guard overrode the model.

## DRY + SOLID

- **DRY** — the audit record is produced by the ONE existing `@audited` interceptor (no second
  writer, no edit to it); the span is produced by the ONE `observability.span` helper. The
  decision is serialised once by `PlanDecision.model_dump`.
- **SOLID: S** — the node emits the fact; the interceptor owns the record; the span writer owns
  the line format. **O** — a new fact is a new attribute, not a new writer.

## Tasks

1. **`graph/planning.py` — the decision span.** Inside `plan`, open
   `span("decision", "plan", attributes=...)` with the structural facts only: `action`,
   `step`, `budget_left`, `overridden`, `proposed_action`. Never the rationale, the complaint
   or the note (D7-08). `finish_investigation` emits the closing `decision` fact (action and
   step, or the bypass marker when the emergency arm skipped `plan`).

2. **`observability/spans.py` — declare the fourth kind.** Add `"decision"` to the documented
   kind vocabulary with a one-line rationale (a planner decision is neither a node, a tool nor
   a model call). No format change.

3. **`tests/test_plan_audit.py` (new).** Drive the shipped graph with the REAL
   `plan_next_step` tool (model stubbed) and the injected in-memory store: assert exactly one
   `plan_next_step` audit record per decision, that its `outputs` carry `action`, `rationale`,
   `step` and `overridden`, and that the span stream carries the matching `decision` span with
   the same action and step. Also prove a guard override is recorded as `overridden: true` with
   its `override_reason`.

4. **Docs truth pass.** `mcp/server.py`'s module docstring and `docs/MCP.md` §5 currently say
   `plan_next_step`/`request_clarification` are allowlisted but uncalled. They are now on the
   shipped path; state that, and keep the nine-tool surface description accurate. Update the
   packaged skill only where it makes the same claim.
