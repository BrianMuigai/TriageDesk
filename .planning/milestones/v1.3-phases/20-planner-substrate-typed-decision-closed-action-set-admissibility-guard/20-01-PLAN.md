# Phase 20 · Plan 01 — Typed decision contract + pure planner policy

## Objective

Land the closed action set and the deterministic admissibility policy as **pure code**, before
anything can call a model or move a graph edge. After this plan, `core/planner.py` alone answers
"what may happen next?", and the answer can only ever be one of four read-only actions or the exit.

## DRY / SOLID compliance (iron-clad, `docs/CONVENTIONS.md`)

- **DRY** — one declaration per fact: the four action names exist only as `PlanAction` members
  (no string literal for an action anywhere else); `MAX_INVESTIGATION_STEPS` is declared once in
  `core/schema.py` beside the contract default that reads it and is **re-exported** by
  `core/planner.py` as the policy's own name — the value `3` is never written twice.
- **DRY** — no SATS value is introduced at all: the planner reads no band, colour or threshold, so
  `data/*.yaml` stays the only clinical authority.
- **SOLID:S** — `core/planner.py` does policy only: it never calls a model, never touches the store,
  never formats a citation.
- **SOLID:O** — a new action is a new enum member plus one admissibility clause; `validate_proposal`
  and `default_plan` are unchanged by it.
- **SOLID:I** — `InvestigationState` carries exactly the ten facts the policy reads, so the tool's
  input cannot carry a field the policy ignores (`extra="forbid"` makes that structural).
- **SOLID:D** — the guard depends on the `PlanAction`/`PlanProposal` contracts, not on the model
  wrapper or the MCP server.

  <name>Task 2: Write the pure policy module `core/planner.py`</name>
  <files>src/triagedesk/core/planner.py</files>
  <action>
    Create `src/triagedesk/core/planner.py` (module docstring: pure, ADAPT-02/06/08, imports nothing
    from `llm`/`mcp`/`store`, no SATS value, cites `tests/test_purity.py`). Import only from
    `triagedesk.core.schema`. Declare:

    - `from triagedesk.core.schema import MAX_INVESTIGATION_STEPS` and put it in `__all__` — the
      policy's name for the ONE bound declared beside the contract default.
    - `FINISH_ONLY: frozenset[PlanAction]` = the single exit — the ONE value the tool's fast path
      compares against (no second literal set).
    - `admissible_actions(state: InvestigationState) -> frozenset[PlanAction]`:
      `finish_investigation` is **always** admissible; when `state.budget_left > 0` also add
      `gather_evidence` if `not state.has_evidence` and it is not in `state.history`, `ask_question`
      if `state.retrieval_status == "ambiguous"` and `state.candidates` and
      `state.clarification_round < 1` and it is not in history, and `re_extract` if
      `state.missing_vitals` and it is not in history. When `budget_left <= 0` return `FINISH_ONLY`
      (nothing else is admissible).
    - `_next_counters(state) -> tuple[int, int]` — `(state.step + 1, max(state.budget_left - 1, 0))`,
      the ONE monotone-decrement rule every decision uses (ADAPT-06: never raises, never loops).
    - `default_plan(state) -> PlanDecision` — always `finish_investigation`, `overridden=False`,
      `proposed_action=None`, counters from `_next_counters`. Docstring: this is exactly today's
      behaviour and the Phase 24 baseline arm.
    - `validate_proposal(proposal: PlanProposal | Mapping[str, Any] | None, state) -> PlanDecision`
      — `None` → override ("no proposal was produced"); a mapping that fails
      `PlanProposal.model_validate` → override ("malformed"); an action not in
      `admissible_actions(state)` → override naming the action and, when the budget is spent, saying
      so; otherwise an accepted decision carrying `proposed_action` and `overridden=False`.
      `_override(...)` is the ONE degradation shape. The guard NEVER returns an action outside
      `admissible_actions(state)`.
    - Document that `PlanProposal.focus` is deliberately **not** forwarded: an action's input is
      derived from typed state, so a model string cannot steer a tool call.

    `__all__` = `["FINISH_ONLY", "MAX_INVESTIGATION_STEPS", "admissible_actions", "default_plan", "validate_proposal"]`.
  </action>
