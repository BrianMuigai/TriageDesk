# Phase 22 · Plan 01 — The deterministic pre-check and the fast arm

## Objective

Add a pure pre-check that lets a structured case the scorer already puts in the most urgent band
reach the kernel without waiting for extraction — and wire it as one new node before `normalize`,
skipping `normalize` only on the fast arm.

## DRY / SOLID compliance (iron-clad, `docs/CONVENTIONS.md`)

- **DRY** — scoring is not re-implemented: `assess_emergency` calls the kernel's own
  `core.scorer.score_priority(case, [])`. There is no second band table and no second TEWS loop.
- **DRY** — the most urgent colour is derived from `core.rules.colour_urgency()`, the ONE
  data-derived acuity order the waiting room already uses. No colour token is inlined.
- **SOLID:S** — `core/emergency.py` decides *whether to skip the model*; it does not score, route,
  persist or render. The node writes two channels (`emergency`, `route`); the router chooses.
- **SOLID:O** — the graph grows by one node and one conditional edge. `normalize`, `score`,
  `ground`, `verify`, `recheck`, `assess`, the gate and the commit are untouched.
- **SOLID:D** — the node depends on the `CaseInput` contract and the pure `assess_emergency`
  function, not on any model, MCP client or store.
- **EMERG-02** — the verdict contract has no colour/priority/target field, so a pre-check colour is
  *unrepresentable* rather than merely discouraged (mirrors `EvidencePassage`).

  <name>Task 1: Declare the pure emergency pre-check</name>
  <files>src/triagedesk/core/emergency.py</files>
  <action>
    Create `src/triagedesk/core/emergency.py` with:

    ```python
    class EmergencyVerdict(BaseModel):
        fired: bool
        reason: str = ""
        trigger: list[str] = Field(default_factory=list)

    def assess_emergency(case: CaseInput) -> EmergencyVerdict
    ```

    `assess_emergency` calls `score_priority(case, [])` and:
    - returns `fired=False` with the score's own `reason` when it abstained / is out of scope;
    - returns `fired=False` with a "scored vital is missing" reason when `missing_vitals` is non-empty;
    - derives the most urgent band with `max(colour_urgency(), key=...)` and fires only when the
      score's colour equals it, recording human-readable facts
      `["colour=<colour>", "tews=<total>"]` in `trigger`;
    - otherwise returns `fired=False` naming the scored colour.

    Docstring must state that the module is pure, that the pre-check never emits a colour, and that
    `data/sats_tews.yaml` (via the loaders) remains the only SATS source.
  </action>
  <verify>
    <automated>uv run python -c "from triagedesk.core.emergency import assess_emergency, EmergencyVerdict; print('ok')"</automated>
  </verify>
  <done>`EmergencyVerdict` and `assess_emergency` exist; the module imports nothing from `llm`/`mcp`/`store`; no colour literal appears in it.</done>
</task>
