# Plan 24-02 — Measure both arms, publish the delta

## Objective

Run the same 24-case × 3-run suite twice — once with the planner, once without — in **real**
mode on `qwen2.5:1.5b`, and publish the comparison from the two sealed reports through the ONE
generator. No number is retyped; the delta is whatever the runs produced.

## DRY + SOLID

- **DRY** — one generator, one analyser, one report schema. The comparison is rendered from
  the two `Report` objects through `analyse()`; the script never computes a second, divergent
  metric. The comparison block is fenced by stable markers and replaced in place, exactly like
  every other generated section, so re-running is byte-identical.
- **SOLID: S** — the runner measures; the generator renders; the analyser aggregates. The
  generator gains one section renderer, not a second pipeline.
- **SOLID: L** — `render_evals(template, report)` keeps its contract; the baseline is an
  optional second argument, so every existing caller and test is unchanged.
- **SOLID: D** — both arms are ordinary `Report` values; the generator depends on the report
  contract, not on how the arm was run.

## Tasks

### Task 1 — run the adaptive arm in real mode

`type="auto"`

```bash
uv run triagedesk eval --cases evals/cases --runs 3 --report evals/results/report.json
```

Generous timeout (~45 min). Before publishing, diff every case's `outcomes` against the
committed v1.2 report: **if any colour changed, STOP and report — do not tune.**

**Verify:** report validates, `mode == "real"`, 24 cases, `gate.passed is True`.

### Task 2 — run the baseline arm in real mode

`type="auto"`

```bash
uv run triagedesk eval --cases evals/cases --runs 3 --no-planner \
  --report evals/results/report.baseline.json
```

The baseline must reproduce the same colours on the same cases; its
`investigation_steps` are all `None`.

**Verify:** `mode == "real"`, `planner is False`, `analysis.adaptive.runs_with_investigation == 0`.

### Task 3 — one generated comparison section

`type="auto"`

- Add `--baseline` (default `evals/results/report.baseline.json`) and
  `render_evals(template, report, baseline=None)`.
- Add a fenced `<!-- BEGIN GENERATED: comparison -->` block under a hand-written
  `### 3.3 Adaptive vs baseline — the measured delta` heading in `EVALS.md`, inserted after
  the generated source block. The table names, per arm: colour correctness, coverage
  (delivered/runs), clarified, deferred, mean steps, guard-override rate, p50 and p95. A
  following line states the **delta** for the headline metrics and the arm's mode.
- `--check` validates BOTH report digests and exits 0 only when `EVALS.md` matches.

**Verify:** `uv run python scripts/emit_evals.py --check` → 0; run twice, byte-identical.
