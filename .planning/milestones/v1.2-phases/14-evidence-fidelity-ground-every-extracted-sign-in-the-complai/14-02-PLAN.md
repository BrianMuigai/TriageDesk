<objective>
Carry the committed target through an approval edit, beside the committed colour.

Purpose: Phase 13 made `CommitResult` report the colour the queue row holds, and `handover`
prefers it. The target was left behind: `CommitResult` has no `target` field,
`commit_priority` calls `commit_to_queue` without one, and `handover` always renders
`priority.target`. After an edit that changes the colour, the card can therefore show the scored
target time next to the committed colour — two facts that disagree about the same patient.

Output: a typed `CommitResult.target` populated from the persisted row, a target derived from the
committed colour through the loaded substrate, one helper that owns "the committed field wins",
and the edit/fallback regression suite.

**Safety argument.** This plan adds no route to the queue and no new colour source. The committed
colour is still the clinician's `final_colour` (edit) or the scored colour (approve); the target is
a pure lookup of that colour in `data/sats_tews.yaml`, the same table the scorer uses. A refusal
still touches no store. The idempotency key, the audit record and the graph topology are
unchanged; only what the card reports after a committed edit becomes consistent with the row.
</objective>

## Safety argument (stated once, proven by the suite)

- **The committed colour rule is untouched.** `core/approval.committed_colour` still returns the
  clinician's `final_colour` for an edit and the scored colour for an approve.
- **The target is data-derived.** `target_for_colour` reads `get_tews().target_times`; it returns
  `None` for an undeclared colour rather than raising or inventing one.
- **No new write path.** Only `commit_priority` writes, and only after a validated token. The
  refusal branches return before any store access, exactly as today.
- **No new colour.** The card can only show a colour the gate already committed or the scorer
  already produced.

## Risk & rollback

- **Risk: an edit offers a colour with no declared target.** `ApprovalToken` already rejects an
  undeclared edit colour; `target_for_colour` additionally degrades to `None` instead of raising.
- **Risk: the stand-in gate change breaks a graph test that relied on the old row colour.** That
  old behaviour was a divergence from the shipped gate; the full suite is the gate, and any
  failure indicates the test was asserting the divergence.
- **Risk: a second copy of the committed-field conditional appears.** The helper is the only home;
  the review check is that `handover` contains no `commit_result.colour`/`.target` conditional.
- **Rollback:** revert this plan's commit. The schema addition is optional, the store already
  supports `target`, and no data migration is required.
