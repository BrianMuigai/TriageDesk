<objective>
Ground every sign an extraction claims against the note it came from.

Purpose: `ExtractionResult` currently carries `case`, `matched_discriminator_ids` and
`no_discriminator_matched` (`core/schema.py:81-91`) with no evidence field, and
`normalize_case` only filters model ids to the closed set. A model (or a note that talks to the
model) can therefore return a declared id or a vital the note never stated, and the tool contract
would report it as fact. The model already drops unstated numeric values inside the model client
(`llm/notes.py::_drop_unstated`), but the rule is private to `llm/`, so a caller that reaches the
tool with an injected extraction gets no check at the boundary.

Output: one narrow, pure module (`core/grounding.py`) with one public function, used by
`normalize_case`, plus the DRY move that makes the numeric-stated predicate shared with the
existing model-client grounding step, and the E-13 regression suite.

**Safety argument.** Grounding can only remove evidence, never add it: the id set is a subset of
the already-closed-set-filtered input, and every vital is either its input value or `None`. There
is no new colour source — the deterministic scorer still computes every colour and citation — and
no new route to the queue. A dropped genuine sign can only lower acuity or trigger the existing
deferral/re-measure terminal, both of which fail closed. The gate, the audit chain and the
deferral logic are unchanged.
</objective>

## Safety argument (stated once, proven by the suite)

- **Removal only.** `ground_extraction` filters the input id list and nulls unsupported numeric
  values. It never constructs an id, never invents a value and never touches colour, target or
  destination.
- **No new colour source.** The scorer remains the only place a colour is computed; the grounded
  ids are only an input to it.
- **Fail-closed direction.** Dropping a genuine sign can lower acuity or set
  `no_discriminator_matched`, which routes to the shipped deferral/re-measure terminals — never to
  a higher colour and never to a commit without the gate.
- **No eval tuning.** The fixtures, the thresholds, the harness and `EVALS.md` are not touched.
  The measured E-13 status stays exactly as recorded.

## Risk & rollback

- **Risk: grounding drops a legitimately inferred discriminator.** A model may select a declared
  id from a synonym the note does not literally contain. That lowers acuity or triggers the
  existing deferral terminal — safe, but it can change measured eval outcomes. Mitigation: the
  rule requires only one declared alias, the alias lists are broad, and the graph independently
  re-matches the complaint deterministically. No eval fixture or threshold is tuned.
- **Risk: a second matcher or an inline alias list appears.** The module reuses
  `matcher.alias_matches` and reads aliases only from `get_discriminators()`;
  `tests/test_no_duplicated_sats.py` and the purity guard back this up.
- **Risk: the `llm/notes.py` move changes behaviour.** The move is mechanical; the unedited
  `tests/test_llm_notes.py` suite is the gate.
- **Rollback:** revert this plan's commit. No data, schema, queue or audit shape changes, so
  reverting restores the previous tool contract with no migration.
