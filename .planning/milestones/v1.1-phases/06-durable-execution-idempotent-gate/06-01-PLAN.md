<objective>
Change the queue row's identity from the scored colour to the immutable case input, and make an
`edit` decision supersede the existing row in place instead of inserting a second row.

Purpose: retire the milestone's core idempotency-key breadth bug (AGENT-01 / success criterion 2) at
the published store and tool seams, so an approve and an edit of the same case cannot fork identity.
Output: a schema-derived key, a supersede write in `commit_to_queue` and both `Store` implementations,
a widened `commit_priority(case_id, colour, case, approval_token)` contract, and every call site and
churned test updated in the same wave.
**CONTEXT decisions implemented:** D6-04, D6-05, D6-06, D6-07.

**User story (ROADMAP Phase 6 Goal):** **As a** triage nurse, **I want to** have a corrected priority
replace the queued one for the same patient, **so that** the patient appears exactly once in the queue
with the priority I approved.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| MCP client → owned tool | Untrusted tool arguments (`colour`, `case`, `approval_token`) cross into `commit_priority`. |
| owned tool → store seam | The immutable case payload becomes the idempotency key of a persisted queue row. |
| tool arguments → SQL | `BorrowedStore` values cross into the borrowed SQLite `query` tool. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-01 | Tampering | `store/queue.py` + `store/borrowed.py` idempotency key | high | mitigate | Key on `hash_value({case_id, **immutable CaseInput fields})` and keep the `PRIMARY KEY (case_id, content_hash)`; the `ON CONFLICT ... DO UPDATE` form updates only `colour`/`target`, so a different case can never overwrite another case's row. |
| T-06-02 | Tampering | `mcp/server.commit_priority` `case` parameter | medium | mitigate | `case` is a typed `CaseInput` validated by the ONE schema module (`core/schema.py`); no `**kwargs`, no dict passthrough into the key. |
| T-06-03 | Repudiation | queue write vs audit record | high | mitigate | The refusal path stays before the store call and the `@audited` interceptor is left unchanged, so every call still appends exactly one chained record; a supersede is still one audited call. |
| T-06-SC | Tampering | package installs | high | accept | No package is installed by this plan (no new dependency); no legitimacy gate is required. |
</threat_model>
