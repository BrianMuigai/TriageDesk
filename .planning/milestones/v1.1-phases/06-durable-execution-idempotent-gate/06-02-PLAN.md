<objective>
Make the durable `checkpointed_graph` the real execution path: `demo --durable` runs one case to the
approval gate over `checkpoints.db`, prints the content-derived `thread_id` and the exact `resume`
command, and exits; `triagedesk resume` reopens the same file in a fresh process and drives the gate to
a committed handover. All pause/resume plumbing lives in ONE helper so the demo and the CLI cannot
drift.

Purpose: turn AGENT-01's headline into a demonstrable, provable property — a paused case survives a
process restart — and satisfy ROADMAP Phase 6 success criteria 1, 3 and 4.
Output: `src/triagedesk/durable.py`, a `resume` subcommand, a `--durable` demo mode, the restart and
exactly-once proofs, and the documented two-command durability story.
**CONTEXT decisions implemented:** D6-01, D6-02, D6-03, D6-08, D6-09, D6-10, D6-11, D6-12, D6-13, D6-14, D6-15.

**User story (ROADMAP Phase 6 Goal):** **As a** triage nurse, **I want to** pause a triage decision and
resume it later without losing it, **so that** a restart mid-decision never loses a patient or writes a
duplicate.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CLI args → resume decision | Untrusted `--approver`/`--role`/`--colour` cross into the graph's resumed value. |
| checkpoints.db → process 2 | The desktop file is untrusted input to the second process's deserialiser. |
| resume value → committed colour | The resumed decision drives the gated commit's `final_colour`. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-04 | Tampering / Elevation | `graph/build.checkpointed_graph` deserialiser | high | mitigate | The `JsonPlusSerializer` allowlist is already derived from `core.schema` and explicit; this plan adds no allowlist entry and never passes `True`; a resumed value is a plain `dict`. |
| T-06-05 | Spoofing | `durable.approval_decision` / `resume` CLI | high | mitigate | `--approver`/`--role` are required at runtime for `approve`/`edit` and rejected when empty; `ApprovalToken.approved_by`/`role` keep `min_length=1`; no fabricated default identity. |
| T-06-06 | Tampering | resumed decision → `final_colour` | high | mitigate | The resume value is copied verbatim by `_build_token` (never invented) and validated by `ApprovalToken` (colour checked against the loaded substrate); a `dismiss` is refused before the store is touched. |
| T-06-07 | Tampering | SQL reached through the durable commit path | medium | mitigate | The borrowed write stays parameterised (`values=[...]`); this plan interpolates no case content into SQL. |
| T-06-SC | Tampering | package installs | high | accept | No package is installed by this plan (no new dependency); no legitimacy gate is required. |
</threat_model>
