# Phase 10 — UI Design Contract

> Visual and interaction contract for the desk-facing surface. Generated by gsd-ui-researcher,
> verified by gsd-ui-checker. Every value below is **prescriptive** — the executor implements it
> without design ambiguity. Architecture (one local HTML page, stdlib `http.server`, no build step,
> no new dependency) is **locked** by D10-01…D10-16 and is not re-opened here.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | none — hand-authored semantic HTML + hand-authored CSS served as a local static asset (`desk/static/styles.css` via `<link>`); no build step, no bundler, no CSS framework, no CDN (D10-01/D10-16). The CSS lives in a `.css` file rather than an inline `<style>` block so no SATS colour/band literal ever appears in Python source (the no-duplicated-SATS guard is scoped to `src/**/*.py`). |
| Icon library | none — every signal is a **text label**; any decorative glyph is a Unicode character drawn from the system font, never a fetched asset or icon font (offline, no CDN — D10-03) |
| Font | system stack only: `-apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, Helvetica, Arial, sans-serif`; no webfont request (offline, no egress — D10-03) |

**Why no design system:** the project is a Python stdlib application with zero front-end tooling.
Introducing shadcn/Tailwind would add a build step and a dependency, both forbidden (D10-01, D10-16).
The contract therefore declares its own minimal token set below rather than inheriting one.

## Spacing Scale

Declared values (multiples of 4 only):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Glyph-to-text gaps, inline padding inside chips |
| sm | 8px | Label→value gap, gaps between adjacent buttons |
| md | 16px | Default element spacing; gap between form rows |
| lg | 24px | Card inner padding; gate panel inner padding |
| xl | 32px | Gap between the card and the gate panel |
| 2xl | 48px | Major section break (quickstart → form → result) |
| 3xl | 64px | Page top and bottom margin |

**Exceptions:** interactive controls (text inputs, selects, radio cards, buttons) have a **minimum
target height of 44px** (WCAG 2.5.5 Target Size). 44px is itself a multiple of 4, so no spacing token
is broken — the 44px is a *control height*, not a spacing step. No other exception.

## Typography

Exactly four sizes, exactly two weights (400 regular, 600 semibold). No italic, no third weight.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 | 1.5 |
| Label | 14px | 600 | 1.4 |
| Heading | 20px | 600 | 1.2 |
| Display | 32px | 600 | 1.15 |

**Reserved uses (do not reuse for decoration):**
- **Display (32px)** — the banner headline, and the suggested-colour name on the priority card. Nothing else.
- **Heading (20px)** — the page `h1`, the card heading, the gate heading, and each section heading.
- **Label (14px / 600)** — field labels, card field labels, the colour text label, button text on secondary controls.
- **Body (16px)** — all prose, field values, citation strings, list rows.

Rationale: a nurse reads this under pressure; 16px body at 1.5 is the floor for legibility, and only
two weights keeps hierarchy unambiguous without relying on colour.

## Color

### Base palette — 60 / 30 / 10

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#F7F8FA` | Page background — the single largest surface |
| Secondary (30%) | `#FFFFFF` | Card, gate panel, form panel, quickstart panel (each with a 1px `#D0D5DD` border) |
| Accent (10%) | `#1D4ED8` | See the reserved-for list below — never anything else |
| Destructive | `#B42318` | The **Clear form** action only (loses typed vitals; confirmation required) |

Body text on Dominant/Secondary: `#111827` (≈16:1 on `#F7F8FA`). Muted/secondary text: `#475467`
(≈7:1 on `#FFFFFF`). Borders: `#D0D5DD`.

**Accent reserved for** (explicit, exhaustive — never "all interactive elements"):
1. The fill of the primary **CTAs** — the form's **Get suggested priority** and the gate's
   **Approve suggestion** buttons.
2. The keyboard **focus ring** (`outline: 2px solid #1D4ED8; outline-offset: 2px`) on every
   interactive control — inputs, selects, radios, buttons, links.

The quickstart panel renders its four steps as one prose line with no step indicator, so there is
no "active step" to accent — the accent is not used there.

The accent is **never** used for: the priority colour, the banner, evidence rows, body text, card
chrome, or any non-interactive surface.

### Semantic priority tokens — the five SATS colours (data-driven, **outside** the 60/30/10 budget)

These are **semantic**, not decorative, so they do not count against the accent budget. The colour
**name** is read from the substrate (`data/sats_tews.yaml` `tews_to_colour` and `target_times`);
the hex below is the **presentation swatch** the surface maps that name to. Mapping a substrate
colour string to a CSS custom property is presentation, not re-derivation of a clinical value
(D10-02/D10-04) — the surface must never compute which colour applies.

| Token | Fill | On-colour text | Contrast | Label (always rendered as text — D10-08) |
|-------|------|----------------|----------|------------------------------------------|
| `--colour-red` | `#B3261E` | `#FFFFFF` | 6.7:1 | the word **RED** + its target time from the substrate |
| `--colour-orange` | `#9A3412` | `#FFFFFF` | 7.4:1 | the word **ORANGE** + its target time from the substrate |
| `--colour-yellow` | `#FACC15` | `#111827` | 11.7:1 | the word **YELLOW** + its target time from the substrate |
| `--colour-green` | `#15803D` | `#FFFFFF` | 5.0:1 | the word **GREEN** + its target time from the substrate |
| `--colour-blue` | `#0B3D91` | `#FFFFFF` | 10.2:1 | the word **BLUE** + its target time from the substrate |

**Hard rule (D10-08):** a priority colour is **never** rendered as a bare swatch. Every appearance of
a colour is accompanied by its colour name in text and, on the card, by its target time. A colour
whose name is not shown is a defect.

`--colour-blue` is declared for completeness because the substrate's `target_times` names BLUE, but
the current `tews_to_colour` bands never produce it. The surface renders whatever colour string the
graph supplies; it never decides that BLUE is unreachable.

## Interaction & State Contract

The surface is a **thin bridge** (D10-02): it renders graph outputs and never scores, routes, gates,
or writes (D10-04). States are driven by the typed values it receives.

| State | Trigger | What renders |
|-------|---------|--------------|
| **Empty** | No case submitted yet | Quickstart panel + empty vitals form. `priority-card` and `approval-gate` are absent (not merely hidden). Copy: Empty state heading/body. |
| **Loading** | Form submit in flight, or gate decision in flight | CTA is `disabled`, label swaps to `Getting the suggested priority…`; no spinner is required. No second submit is possible. |
| **Populated** | Scored case reaches the gate (`approval_gate` interrupt payload present) | `priority-card` with colour name + label, target time, why-vitals + adjacent citations, evidence list, then `approval-gate`. |
| **Deferred** | `confidence.deferral == true` (from `assess`) | `uncertainty-banner` **and** a **read-only card** — there is **no gate** on this path (owner decision 2026-10-13): the deferral routes to a terminal (`escalate`/`request_missing_info`), so there is no scored suggestion to approve and nothing can be queued. The card shows what the system computed from vitals alone, explicitly framed as **not confirmed and not queued**. |
| **No-match** | `no_match == true` (from `MatchResult`) | `uncertainty-banner` fires with its trigger-conditional body; identical treatment to Deferred — one banner, one rule: fire when the typed signal fires, with **no gate** (a `no_match` case always defers, D8-11). Only the banner BODY string varies with the trigger, so the banner never asserts a fact its trigger did not establish. |
| **Committable** | `no_match == false` AND `confidence.deferral == false` | The card renders the **suggested** colour/target/citations and the **real approve / edit / dismiss gate** is present. No banner (the typed signal did not fire). This is the ONLY path on which a gate appears, and the only path to a queue row. |
| **Gate pending** | The interrupt is outstanding | `approval-gate` visible; approve/edit require `Your name` and `Your role` (non-blank — whitespace-only counts as absent); edit additionally requires a chosen colour from the five SATS names. |
| **Committed** | Resume returned a `CommitResult` with `committed == true` | Success panel with the Committed copy; the gate controls are replaced (no second decision). |
| **Dismissed** | Decision was `dismiss` | Neutral `--muted-bg` panel with the Dismissed copy. **No artefact committed.** |
| **Timeout** | The client deadline elapses before a decision | Neutral `--muted-bg` panel with the Timeout copy. **No auto-approve, no default colour, no commit.** The gate is closed. |
| **Error** | Schema rejection, or a server/graph failure | Error panel with the matching copy; the gate stays unresolved on a failure — a failure never becomes an approve. |
| **Terminal (deferred/escalated/recovery)** | The graph stops before the gate | The matching terminal copy; no card colour, no gate. |

**Fail-safe rules (binding — a regression is a challenge disqualifier):**
1. **Timeout defaults to NO approve.** There is no default colour and no auto-commit path (D10-10).
2. **Dismiss commits nothing.** The surface writes nothing on dismiss (D10-12).
3. **The surface never commits on its own.** The only route to a queue row is the resumed
   `approval_gate` interrupt through the gated `commit_priority` tool (D10-11/D10-12).
4. **A failure is never an approve.** Any error leaves the decision unresolved.

**Accessibility rules (binding):**
1. **Colour is never the only signal** (D10-08): every colour carries its name as text; the banner
   carries a text headline; state panels carry text.
2. Contrast: all text meets WCAG AA (≥4.5:1); the ratios in the colour tables are the contract.
3. Every interactive control has a visible focus ring (accent token) and a ≥44px target.
4. The uncertainty banner is an `aria-live="polite"` region so it is announced when it appears.
5. The gate is a real `<form>`; the three actions are a radio group + a single submit, or three
   labelled buttons — never colour-only controls.
6. No motion is required to understand any state; a timeout must not rely on an animation to be
   noticed.

## Presentation Boundary (DRY guard)

Binding on the executor; the code-review and verifier gates check it:

- The surface **renders** the graph's typed outputs — the `approval_gate` interrupt payload, the
  `PriorityResult`, the `evidence` channel, and the `ConfidenceResult` — and **never re-derives** a
  colour, a citation, a target time, or a confidence value (D10-02/D10-04/D10-07).
- Every citation string is taken from the ONE citation helper's output already carried on the
  payload; the surface **never formats or inlines** a citation (D10-06).
- Every target time and destination comes from the substrate via the payload; the surface never
  restates a band or threshold (CONVENTIONS §1).
- The only mapping the surface owns is **presentation**: a substrate colour string → a CSS custom
  property, and a substrate colour string → the text label already shown beside it. This mapping is
  a lookup, not a computation, and it produces no clinical value.
- The vitals form validates through the ONE shared schema (`CaseInput`) and surfaces that schema's
  own rejection; it adds **no** second validation rule (D10-13).
