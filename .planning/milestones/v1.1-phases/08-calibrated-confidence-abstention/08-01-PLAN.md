<objective>
Give the triage graph a deterministic coverage/deferral signal that can only ever make the system **more cautious**. A new pure `core/confidence.py` computes the signal from four already-typed objects the graph holds after `score`; a new owned MCP tool `assess_confidence` exposes it; a new `assess` node writes it to a new state channel and routes a deferral to `escalate`/`request_missing_info` — terminals with no edge to `commit`.

Purpose: satisfy the ROADMAP success criteria 1–3 for AGENT-02 at a published seam (new core module + new tool + new node), editing neither the scorer's arithmetic, the citation helper, nor the audit interceptor (D-18).
Output: the confidence contract, the pure signal module, the sixth owned tool, the `assess` node + routing, the allowlist/factory update, the one-way-safety proof suite, and the D20 asymmetric-cost decision.

**Node placement — relocation (binding; verified against the real edges before starting).** `assess` sits **immediately before `approval_gate`**, i.e. the pipeline is `score → verify → recheck → assess → approval_gate`, NOT `score → assess → …`. Rationale: the deferral's purpose is to prevent a **commit**, not to suppress the **deterministic safety recheck**. Placing `assess` after `recheck` means a `no_match` case still runs the deterioration recheck (`raise_recheck_flag` is still reached; E-07's RECHECK finding stands), while the deferral still routes away from `approval_gate`, so nothing commits. Concretely, and verified against `graph/build.py`'s real edges:
- `route_after_score` and the `score` conditional-edge mapping are **left untouched** (its neutral arm still maps to `"verify"`);
- `recheck`'s successor becomes `assess`: the direct `recheck → approval_gate` edge at `:226` is replaced by `graph.add_edge("recheck", "assess")`;
- `assess`'s conditional edges are `{"escalate": "escalate", "request_missing_info": "request_missing_info", "approval_gate": "approval_gate"}` — the **neutral (non-deferral) arm is `approval_gate`**;
- `escalate` and `request_missing_info` still have **no edge to `commit`** (the structural guarantee), and `graph.add_edge("escalate", END)` / `graph.add_edge("request_missing_info", END)` are unchanged;
- the `vitals_coverage` component is still computed and returned by the tool; on this path `request_missing_info` is **defensive/unreachable via the deferral** (a deferral only occurs after `route_after_score` has already sent any `missing_vitals` case to `request_missing_info`), so the deferral arm routes to `escalate` in practice. That is stated explicitly rather than pretended.
This remains consistent with the locked D8-08 ("a NEW `assess` node placed after `score`") — the node is still after `score`.
