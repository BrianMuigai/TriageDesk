<objective>
Prove the phase architecture end-to-end on the thinnest real slice: a raw triage note flows through the
full LangGraph `ingest -> normalize -> retrieve -> score -> verify -> approval_gate -> commit -> handover`
path on the **local** open-weights model, pauses at a LangGraph `interrupt()` for a named clinician, and
**refuses to commit** when resumed without a valid approval token.

**As a** triage nurse, **I want to** have the system physically refuse to place a patient in the queue
without my explicit named approval, **so that** no patient is ever queued without clinician sign-off.

Purpose: The gate is the phase's protected headline (D-05). This tracer fixes the graph shape, the
checkpointer choice, and the interrupt-before-write ordering on one real path before any expansion, so
an architectural dead-end is caught after one commit instead of after ten.
Output: The `graph/` package (state, nodes, builder), the `HandoverCard` contract, the end-to-end tracer
spike, and the tracer proof suite.

Wire ONE path through every layer the phase touches, on the local model only (D-01, ORCH-02).

Create the `graph/` package. `graph/state.py` defines the ONE typed graph state (`TriageState`, a
`TypedDict`) with fields: `raw_note`, `case` (`CaseInput | None`), `matched_ids` (`list[str]`),
`no_match` (`bool`), `priority` (`PriorityResult | None`), `approval` (`dict | None`), `commit_result`
(`CommitResult | None`), `handover` (`HandoverCard | None`), `route` (`str | None`), `error`
(`str | None`), `attempt` (`int`). It imports only `core.schema` — no model, no MCP client.

`graph/nodes.py` implements thin node functions that depend on an injected `tools` mapping
(name -> async callable), never on a concrete adapter (D-13, SOLID: D). Nodes:
- `ingest`: validate the raw note into an initial state (deterministic; sets `raw_note`, `attempt=0`).
- `normalize`: call the owned `normalize_case` tool on the raw note; store the returned `ExtractionResult.case` (vitals + complaint). The model only structures the note (D-02).
- `retrieve`: call the owned `match_discriminators` tool on `case.complaint`; store `matched_ids` + `no_match`. This is the deterministic authority for the scored discriminator set (never the model's candidate ids).
- `score`: call the owned `score_priority` tool with the typed case and the retrieved ids; store `priority`. The score path touches no model (D-02).
- `verify`: deterministic-first — assert `len(priority.citations) == len(priority.triggered_rules)` and that a non-abstained priority cites at least one rule; set `route="ok"` or `route="retry"`. No model call on this path.
- `approval_gate`: build the evidence payload from `priority` (case_id, colour, target, triggered_rules, citations, missing_vitals, matched_ids, no_match), then call `interrupt(payload)` and store the returned resume value in `approval`. This node MUST perform no side effect before `interrupt()` — a resumed node re-runs from its top (D-04).
- `commit`: build an `ApprovalToken` from `state["approval"]` — carrying `final_colour` (the resume value, defaulting to the scored `priority.colour` when the decision is `approve`) — and call the owned `commit_priority` tool; store `commit_result`. In this plan the tool is the gated stub, so an absent/malformed approval is refused and nothing is written (GATE-02, D-05).
- `handover`: render the `HandoverCard` (see below) from `priority` + `commit_result`; deterministic template only.

`graph/build.py` assembles the `StateGraph`: `START -> ingest -> normalize -> retrieve -> score ->
verify -> approval_gate -> commit -> handover -> END`, using `add_conditional_edges` after `verify`
(`ok` -> `approval_gate`, `retry` -> `score`, bounded by `attempt < 2`). Provide `build_graph(tools,
checkpointer=None)` and an async `run_case(raw_note, tools, config)` entry point. Default `tools` comes
from `mcp/adapter.load_tools()`; the graph depends on the mapping, not the adapter (D-13).

Add `HandoverCard` to `core/schema.py` (the ONE schema module): fields `case_id`, `colour`, `target`,
`citations`, `triggered_rules`, `missing_vitals`, `matched_discriminator_ids`, `no_discriminator_matched`,
`second_look` (`RecheckFlag | None`), `decision`, `approved_by`, `role`. It has NO diagnosis, assessment,
impression, plan or prescription field (the absence of a field is the guard; SAFE-02 is proven in full in
Plan 03-05).

Also extend the existing `ApprovalToken` (same module) with `final_colour: str = Field(min_length=1)` —
the authoritative carrier for the clinician's decision colour, so an `edit` decision has exactly one place
to record the colour the clinician chose (D-05). Validate the value against the colour set read from the
loaded substrate, never a hardcoded literal (CONVENTIONS §1).

`scripts/spike_graph.py`: build the graph with real `load_tools()` + a real local-model run over a fixed
synthetic note; `ainvoke` with `config={"configurable": {"thread_id": "<case_id>"}}`; assert the run
pauses with an interrupt (`result["__interrupt__"]` present) and that no commit occurred; then resume
with `Command(resume={"decision": "dismiss"})` (no named approver) and assert `commit_result.refused`
is true and `handover` renders with the priority's structured fields. Exit non-zero on any failure.
</action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| raw note -> normalize node | Untrusted free text crosses here; the model structures it, never scores it. |
| graph -> approval_gate | The irreversible-action boundary: the only path to a queue write passes the interrupt. |
| resumed approval -> commit | The resume value is untrusted input to the commit node; it must validate a token before any write. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-01 | Spoofing | graph approval_gate -> commit | high | mitigate | Commit builds an `ApprovalToken` from the resume value and calls the gated `commit_priority`; an absent/malformed token is refused and nothing is written (GATE-02, D-05). |
| T-03-02 | Tampering | approval_gate node | high | mitigate | The gate node performs no side effect before `interrupt()`; a resumed node re-runs from its top, so any pre-interrupt write would duplicate (D-04). |
| T-03-03 | Information disclosure | graph -> external model | medium | mitigate | Only the local Ollama client is on the path; a guard test asserts no non-local model provider is imported by `graph/` (ORCH-02). |
| T-03-04 | Elevation of privilege | graph tool surface | high | mitigate | The graph depends on an injected tool mapping; it calls only the declared owned tools and has no shell/HTTP path (allowlisted in full by Plan 03-05, SAFE-03). |
| T-03-05 | Denial of service | verify -> score retry | medium | mitigate | The verify retry is bounded (`attempt < 2`) so a stubborn uncited result cannot loop forever (Pitfall 13). |
| T-03-SC | Tampering | npm/pip/cargo installs | high | mitigate | The borrowed server package (`mcp-sqlite@1.0.9`) was reviewed and pinned in Phase 1 (`evidence/mcp-spike.json`, NOTICE); no new install occurs in this plan. |
</threat_model>
