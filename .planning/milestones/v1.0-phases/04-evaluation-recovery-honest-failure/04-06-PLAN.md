<objective>
Close gap G-2 (the honesty bug): the eval harness reads the residual `priority.colour` when a run has no
interrupt payload, so an aborted-at-END run (fail-closed `verify` -> END) is recorded as a passing colour.
Make the harness record the graph's TRUE terminal behaviour — delivered-through-the-gate vs aborted-at-END —
and never count an abort as a pass, then re-run the REAL measured evaluation and regenerate EVALS.md from
the honest report.

**As a** triage-desk safety reviewer, **I want to** see whether each run actually delivered a card through the
approval gate or aborted at END, **so that** a fail-closed run can never be reported as a passing colour and
the published evaluation proves the system's real behaviour.

Purpose: the phase goal is an HONEST evaluation that PROVES behaviour; a report that maps a card-less abort to
a GREEN pass is the opposite. This plan makes the terminal behaviour first-class and re-publishes the measured
result honestly. Output: an abort-aware capture, a `Gate delivery` metric, and a regenerated EVALS.md from a
real measured report.
</objective>
