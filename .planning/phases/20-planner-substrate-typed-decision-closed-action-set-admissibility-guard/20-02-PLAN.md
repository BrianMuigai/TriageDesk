# Phase 20 · Plan 02 — Model proposal behind the ONE wrapper + the eighth owned tool

## Objective

Let the local model *propose* an action through the single model wrapper, and expose it as one thin,
read-only MCP tool whose return value the guard has already validated. **No graph node is added and
no edge moves.**

## DRY / SOLID compliance (iron-clad, `docs/CONVENTIONS.md`)

- **DRY** — the plan prompt lives in `llm/prompts.py` (the ONE prompt module), never inline at the
  call site; the admissible list in the prompt comes from `core.planner.admissible_actions` (ONE
  policy), not a second restatement.
- **DRY** — `propose_plan_async` reuses `_response_text`, `_async_generate`, `_async_client`,
  `OPTIONS`, the `span("model", …)` shape and the `UsageSink` seam; no second Ollama client and no
  second transport is constructed.
- **DRY** — the action names exist only as `PlanAction` members; the tool, the prompt, the allowlist
  and the tests never restate an action string.
- **SOLID:S** — the tool is an adapter: admissibility comes from `core.planner`, the proposal from
  `llm.client`, the audit from `@audited`. It contains no policy.
- **SOLID:L** — the tool honours the declared `InvestigationState → PlanDecision` contract; a caller
  cannot receive an action outside the closed set.
- **SOLID:O** — the allowlist grows by one name in one commit; no existing tool body changes.
- **SOLID:D** — the tool depends on the planner policy and the wrapper interface, not on Ollama.
- **ADAPT-04** — the tool has no store, no approval token, no colour field: it can only *report* a
  next read-only action.
