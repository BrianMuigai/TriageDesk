<objective>
Make the desk surface model-real without letting the model touch the priority.

Purpose: `desk/pipeline.py:31` builds `offline_tools(case, ...)`, so the desk's `normalize_case` returns the
case's own extraction and the surface never calls the model — a judge sees a desk that does no agentic work.
This plan adds an explicit online mode that runs the REAL extraction on the free-text complaint the form
already posts, precomputes it in the background while the nurse finishes entering vitals (keyed by a hash of
the complaint), and reuses the cached extraction at submit. The default stays offline, and the UI labels which
mode is live.

Output: the desk's ONE online-extraction seam (`desk/extraction.py`), the harness-free `online_tools` entry
point, the `--online` flag, the `POST /precompute` route, the mode label, and the proofs.

**Safety argument.** The extraction feeds the graph's `normalize` node, but `merge_case` overlays every
non-`None` form field on top of it: the nurse's typed vitals always win, and a field the nurse left blank stays
blank unless the note itself stated it (the grounding step in `llm/client` already drops unstated values). So
the case that reaches the deterministic scorer is the nurse's case; the colour and every citation still come
from the scorer. Nothing new can reach `commit` — the approval gate and the gated tool are untouched, and
`desk/` still imports neither `store.queue` nor `mcp.server`. A precompute failure degrades to the normal path
(one in-path extraction, then the graph's structured-case fallback), which is the offline path and therefore
produces the same colour and the same citations.
</objective>

## Safety argument (stated once, proven by the suite)

1. **The model cannot move a vital.** `merge_case(form, extracted)` overlays every non-`None` `CaseInput` field
   of the form on the extracted case. The nurse's values are the merged values, by construction.
2. **The model cannot move the colour.** For the same form case, online and offline produce the same colour and
   citations — asserted directly by comparing two `submit_case` runs (separate checkpoint files).
3. **No uncited priority.** The colour always comes from `core.scorer.score_priority`; the extraction never
   produces a `PriorityResult`. `verify` still blocks any uncited priority.
4. **No new commit path.** The gate is untouched; `desk/`'s import graph is unchanged in the guarded
   dimensions (`store.queue` and `mcp.server` remain forbidden and unimported).
5. **Precompute cannot corrupt the audit chain.** The background extraction calls `llm.client.extract_async`
   directly — it does NOT call the audited owned tool, so it appends no audit record and never races the
   chain-head writer. The audited tool calls still happen exactly once per graph run.

| browser (localhost) -> `POST /precompute` | A new POST route; untrusted complaint text crosses it and it triggers a model call (resource use). |

## Risk & rollback

- **Risk: a model-extracted value slips past the merge.** Mitigated by overlaying every non-`None` form field and
  by the direct colour-equality test; a regression fails the suite.
- **Risk: the precompute task leaks or is orphaned.** Bounded cache, FIFO eviction with cancellation, and
  `take()` pops; the loop is owned by the server and stopped on close.
- **Risk: a new POST route widens the surface.** It reuses the existing guard preamble and returns 204 with no
  body; the CSRF test proves an unauthenticated POST is refused.
- **Rollback:** revert this plan's commit. Offline behaviour is the default, so reverting restores the shipped
  desk exactly; no data migration and no persisted state changes.
