<objective>
Complete the owned server's five-tool surface with the three remaining tools: a contract-validated `normalize_case`, a pure `raise_recheck_flag`, and a gated `commit_priority` stub.

Purpose: The graph (Phase 3) depends on the tool interface, not implementations (D-09). Delivering the full five-tool contract now, each narrow and single-purpose, lets Phase 3 wire the graph against a fixed seam.
Output: `core/recheck.py`, the completed tool surface in `mcp/server.py`, and the recheck/tool-contract tests.
</objective>

## Interface contracts (executor reference)
- Existing `normalize_case(raw_note: str) -> ExtractionResult` calls the model via `llm/client.py`; `ExtractionResult` has `case`, `matched_discriminator_ids: list[str]`, `no_discriminator_matched: bool`.

- New contract additions (default names; field names are the agent's discretion):
  - `RecheckFlag`: `flag: bool`, `deteriorations: list[str]`, `before`/`after` vitals (or per-vital before/after detail), `reason`.
  - `ApprovalToken`: `approved_by`, `role`, `decision` (approve|edit|dismiss), `approved_at`.
  - `CommitResult`: `committed: bool`, `refused: bool`, `reason`.
- Phase 1 verification deferred item: `ExtractionResult.matched_discriminator_ids` is unconstrained; this plan validates it against the closed set (Phase 2 SC3/SC5).
