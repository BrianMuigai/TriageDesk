# Plan 26-01 — Guide a new patient, with the human in the loop at every checkpoint

## Objective

The Phase 25 desk showed the intake form and a chat transcript at the same time. The nurse had to
choose where to record the case, and after scoring the card and gate were buried beside a still-open
form. This plan turns the desk into a guided patient workflow with explicit human checkpoints:

1. **Record** — one structured intake, with an optional note helper above it.
2. **Confirm** — the nurse reviews every value, its provenance, and the gaps before anything is scored.
3. **Review & decide** — the sourced suggestion and the named approval gate; `Edit details` returns to step 1.
4. **Outcome** — the handover/terminal and a clear next-patient action.

No graph run, scorer, or queue write happens before the explicit confirm. The gate remains the only
commit path.

## DRY + SOLID

- **DRY** — labels/bounds remain in `core.schema` + `desk.forms`; copy in `desk.copy`; the step
  vocabulary in one `desk` presentation module; SATS colours in `styles.css`.
- **SOLID: S** — `views` composes; `server` routes the intake actions; `chat` renders the note
  summary; `forms` validates and maps values; `gate` renders the decision.
- **SOLID: O** — a step is a new view branch + a static fragment, not a new graph or a second scorer.
- **SOLID: L** — the confirm and review steps consume the same `CaseInput` contract; the graph still
  receives exactly the one validated case.
- **SOLID: D** — the desk still depends on the graph/tool seams, never on a queue writer.

## Tasks

### Task 1 — Guided step state and the Confirm checkpoint

`type="auto"`

- Add explicit intake actions to `POST /case`: `confirm` (validate + render step 2), `score` (run the
  existing graph path), `back` (return to step 1 with the posted values), and keep the no-action
  default as the score path for existing callers/tests.
- Add a `step` field to every view (`record`, `confirm`, `review`, `outcome`) and a two/three-label
  stepper: `1 Record`, `2 Confirm`, `3 Review & decide`. The outcome is a completion state.
- Step 2 is a read-only summary built from the validated form: every labelled value, the
  "not stated" gaps, and a "From note" badge on values the note supplied. It has exactly two actions:
  `Looks right — get suggested priority` and `Edit details`. No graph is reached from the confirm
  render.
- Carry note provenance from the note prefill into the confirm summary without a new store.
- Keep the named gate, edit-colour disclosure, dismissal, clarification, and recovery paths intact.

**Verify:** `uv run pytest -q tests/test_desk.py tests/test_desk_chat.py tests/test_desk_forms.py`

### Task 2 — Record and Review workspaces

`type="auto"`

- Step 1: full-width structured intake; the note helper is a compact band above it with one textarea
  and one `Fill form from note` action. The form's primary action is `Review details`; no card/gate
  is rendered.
- Step 3: the suggestion card + gate on their own; a separate `Edit details` form (with the paused
  case's hidden values and CSRF) returns to step 1. The full intake form is not always open beside
  the review.
- The outcome state renders the handover/terminal with `Start next patient`.
- Update the stepper, responsive layout, and copy so the next action is unambiguous at 1360px and
  375px.

**Verify:** `uv run pytest -q tests/test_desk.py tests/test_desk_chat.py tests/test_desk_forms.py tests/test_system_page.py`
