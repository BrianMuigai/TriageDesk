citations) — no manual prose (Pitfall 5).

Core layer (D-14/D-15): `core/schema.py` defines the ONE schema module — `CaseInput` (structured vitals,
every vital nullable so nothing is ever imputed, plus an untrusted free-text `complaint: str`) and
`ExtractionResult` (the case plus the model's selected discriminator ids from a closed set and a
no-match signal). Use `Literal` enums for mobility/AVPU so they become JSON-schema enums. This module has
no I/O and imports nothing from `llm`/`mcp`/`store` (D-13). `core/rules.py` loads `data/sats_tews.yaml` once
and returns typed Pydantic models; nothing else parses that YAML.

LLM layer (D-01/D-02/D-03): `llm/client.py` wraps Ollama. It calls `ollama.generate` with
`format=ExtractionResult.model_json_schema()`, `think=False`, and `options={"temperature": 0, "seed": 42,
"num_ctx": 2048}`, then validates the response with `ExtractionResult.model_validate_json`. The `think=False`
flag is mandatory and must be asserted in the wrapper: `qwen3.5:4b` is a reasoning model and without it the
constrained JSON is emitted into the thinking channel and `response` comes back empty. The wrapper must
raise on an empty or unparsable response (never return unvalidated data). The model may only structure the
note and choose discriminator ids — it computes no number (D-03).

MCP layer: `mcp/server.py` builds an `mcp` SDK v2 `MCPServer` (import `from mcp.server import MCPServer`;
the v1 `FastMCP` import path was removed) exposing ONE tool, `normalize_case`, that returns an
`ExtractionResult`; run it over stdio. `mcp/adapter.py` is the single wiring module that exposes
`load_tools() -> list[BaseTool]` using `langchain.mcp.MCPAdapter` against the owned server launched as a
stdio subprocess — this is the DIP seam; callers depend on `load_tools()`, never on `MCPAdapter` directly
(D-04/D-13).

`scripts/spike_e2e.py` runs the whole path once against a fixed synthetic note: load the YAML via the
loader, extract via the client, validate, list the owned tools through the adapter, call `normalize_case`,
and exit non-zero on any failure. This script is the end-to-end verification for the tracer.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| nurse note → parser | Free-text `complaint` is untrusted data and may contain injected instructions |
| local model → core | Model output is untrusted until validated against the one schema |
| process → MCP stdio | Owned server is a subprocess; its tool results cross back into the process |
| package registries → environment | PyPI/model-tag installs are supply-chain input |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-01 | Tampering | `llm/client.py`, `core/schema.py` | high | mitigate | The complaint is parsed into typed fields and treated as data; extraction is grammar-constrained; the model never sets a colour (deterministic scorer is Phase 2). Covered fully by E-13 in Phase 4. |
| T-01-02 | Tampering | `llm/client.py` | high | mitigate | Every model response is Pydantic-validated; the wrapper raises on empty/unparsable output and never returns unvalidated data. |
| T-01-03 | Tampering | `core/schema.py` | high | mitigate | Unit-carrying, range-validated fields reject implausible values (wrong-scale temperature, negative rates) instead of scoring them (Pitfall 5). |
| T-01-04 | Tampering | `llm/client.py`, model tag | medium | mitigate | The model tag is pinned in config and recorded with its licence in the evidence file; data/prompt/schema hashing lands in Plan 04 (SAFE-04). |
| T-01-06 | Information Disclosure | `llm/` | medium | mitigate | Only the local Ollama server is called; no network client is imported on the extraction path; synthetic data only. |
| T-01-SC | Tampering | PyPI/model installs | high | mitigate | Package-legitimacy gate: all PyPI packages here are official and docs-verified (seam false positives documented in 01-RESEARCH.md §Package Legitimacy Audit); any `[ASSUMED]`/`[SUS]` install would require a blocking human checkpoint before install. |
