<objective>
Encode the published adult SATS rule substrate as the project's single source of truth, and prove the
encoding by independent dual transcription plus exhaustive band-edge tests.

Purpose: Roadmap SC1 requires that every TEWS band, colour threshold, discriminator and category live in
exactly one `data/*.yaml` file and nowhere else, re-verified verbatim. This plan produces the data the
deterministic scorer (Phase 2) will read, and it freezes the transcribed expectations before the scorer
exists (Pitfall 11) so the evaluation cannot later be tuned to pass. It also realises the fail-closed
out-of-scope predicate as data (D-09).

Output: complete `data/sats_tews.yaml` and `data/sats_discriminators.yaml`, a dual-transcription diff
script, band-edge and discriminator-shape tests, and a committed verification report with residual
uncertainty flagged in `docs/SATS.md`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| published manual → YAML | Clinical values are transcribed by hand; a transcription slip is a safety defect |
| YAML → code | The rules are data read by a loader; no code may re-derive a band |
| repo → public | The YAML must not become a wholesale reproduction of copyrighted manual content |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-07 | Tampering | `data/sats_tews.yaml`, `data/sats_discriminators.yaml` | high | mitigate | Dual independent transcription diff (exits non-zero on any disagreement) plus exhaustive band-edge tests on both sides; residual ambiguity is explicitly flagged, never guessed (Pitfall 5/11). |
| T-01-04 | Tampering | `data/*.yaml` provenance | medium | mitigate | Each file carries a `version` and `citation`; canonical hashing of the scale data lands in Plan 04 (SAFE-04) so a post-hoc edit is detectable. |
| T-01-SC | Tampering | dependency installs | high | mitigate | No new installs in this plan (data + tests only); the package-legitimacy gate and its blocking checkpoint are handled in Plan 03. |
</threat_model>
