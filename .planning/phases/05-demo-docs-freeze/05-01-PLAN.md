<objective>
Make the frozen system runnable by a stranger in ONE command (DOCS-01) and guard that path in CI (DOCS-03).

Add a `demo` subcommand to the `triagedesk` CLI. It loads a bundled synthetic beat manifest
(`demo/storyboard.yaml`), runs each beat through the **real** graph via the existing seams
(`evals.tools.build_tools` + `graph.build.build_graph`), prints every owned tool call (name +
inputs -> outputs) so the tool path is visible on screen, pauses at the approval gate, and shows the
gated commit **refusing without a named nurse**. Like `evals.runner.run_eval`, the demo injects the
in-memory store into the owned server's seam (`mcp.server.set_store(...)`, restored in a `finally`),
so the offline path launches no borrowed `npx mcp-sqlite` subprocess. The bare `uv run triagedesk
demo` is offline by default (no pulled model). A CI smoke workflow runs that exact bare command.

Purpose: D-01 (`uv run triagedesk demo` on the bundled fixture, offline, from a clean clone) and
D-02 (the CI smoke test runs that exact path). This is packaging, not new capability — no scoring
logic changes.

Output: a `demo` package, a `demo` CLI subcommand, `demo/storyboard.yaml`, `.github/workflows/smoke.yml`,
and `tests/test_demo.py`.
</objective>

  <action>
Add a `demo` package (`src/triagedesk/demo/__init__.py` exporting `run_demo`) and `run.py` with
`run_demo(*, beats: list[str] | None, offline: bool = True, fixture_dir: str = "evals/cases", store: Store | None = None) -> int`.

`run.py` MUST reuse the shipped seams and MUST NOT reimplement them: load cases with
`triagedesk.evals.case.load_cases(fixture_dir)`; build each beat's tool map with
`triagedesk.evals.tools.build_tools(case, offline=offline, recorder=UsageRecorder())`; assemble the
graph with `triagedesk.graph.build.build_graph(tools, checkpointer=InMemorySaver())`; invoke with a
per-beat `thread_id`; when the result carries `__interrupt__`, resume with `langgraph.types.Command`.
Wrap the tool map in a tracer (a small function that maps each callable to one that prints
`[tool] <name> <inputs> -> <outputs>` before returning) so tool calls are visible on screen (D-07).

`run_demo` MUST resolve and INJECT the store the gated `commit_priority` uses — exactly as
`triagedesk.evals.runner.run_eval` does: `resolved = store if store is not None else InMemoryStore()`,
then `server_module.set_store(resolved)` inside a `try`, restoring `server_module.set_store(None)` in a
`finally`. Without this injection the audited tool path falls through `mcp.server._resolve_store()` to
`store.default_store()` and launches the borrowed `npx mcp-sqlite` stdio subprocess, which the offline
demo must never do (D-01, T-05-10). Expose `store` as the one injection seam the demo regression test
uses (SOLID: D).

Declare `demo/storyboard.yaml` as the beat manifest — a YAML list of `{name, case, label}` entries
mapping a beat name to an existing eval case id (routine -> E-01, escalation -> E-02, deterioration ->
E-07, refusal -> E-02, failure -> E-09). The manifest reuses the bundled `evals/cases/*.yaml`
fixtures; it is NOT globbed by `load_cases` (it lives in its own directory and is read directly).

Add the `demo` subcommand to `cli.py` with `--online` (opt into the pulled-model path; the DEFAULT is
the offline golden fixture, so the bare `triagedesk demo` runs from a clean clone with no model
pulled), `--beat NAME` (repeatable), `--list` (print the beat names from the manifest), and
`--fixture DIR` (default `evals/cases`), declaring its defaults once in the same style as the existing
`DEFAULT_*` constants. For this tracer's ONE path, run the `escalation` beat with a NAMED approval
resume value that is a well-formed `ApprovalToken` — `decision=approve`, `approved_by` a synthetic
nurse name, `role` a role string, AND `approved_at` a UTC timestamp (e.g.
`datetime.now(timezone.utc).isoformat()`) — so the gated `commit_priority` validates the token and
writes exactly one queue row and the handover card prints. A resume value missing `approved_at` is
refused as malformed and writes nothing (T-05-11).

Never inline a SATS value: print the colour, target, citations and matched ids exactly as the graph
returns them. The demo path must launch no network and no borrowed server in offline mode (the
default).
