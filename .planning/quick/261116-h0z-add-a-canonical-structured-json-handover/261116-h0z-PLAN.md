# Quick task: canonical structured JSON handover output contract

## Context

The skill teaches a safe tool sequence and a fail-closed terminal, but it never says what the
**machine-readable** result of a triage turn looks like. A harness therefore improvises the shape
of its summary, and a downstream consumer (a desk integration, an eval, an audit reconciler) has
nothing stable to parse.

This task adds one canonical **JSON handover block** emitted at the end of every triage turn,
alongside the short human-readable summary — not JSON-only, not schema-only — plus the reference
schema document and the tests that keep it honest.

Scope is deliberately narrow: **skill markdown + tests + one doc line.** No MCP server, scorer,
graph, or Python behaviour changes.

**No tracer task.** This change touches no runtime layer — there is no vertical slice to prove
(markdown and test assertions only), so horizontal task order is the correct shape here.

## DRY + SOLID notes (iron-clad, CONVENTIONS §1/§2)

| Concern | The one place it lives | Everyone else |
| --- | --- | --- |
| Handover field names, closed sets, invariants, mapping table | `references/output-contract.md` | `SKILL.md` links to it and states only the few invariants an operator must not get wrong |
| SATS bands / colour thresholds | `data/sats_tews.yaml` | both files point at it; neither copies a rule |
| Case + audit field names | the existing typed schema / `references/tool-contracts.md` | the contract reuses those names, never re-declares them |
| Install mechanics | `skills/__init__.py::_skill_files` (recursive walk) | no new copy path is written (S: one copy function) |

The closed-set literals necessarily appear in the test module as the **independent expectation** —
the same pattern the existing fail-closed-vocabulary test uses. That is a contract assertion, not a
second runtime source.

  <name>Task 1: Write references/output-contract.md</name>
  <files>src/triagedesk/skills/triagedesk-triage/references/output-contract.md</files>
  <action>
Create the new reference (Markdown only — this file is package data copied verbatim by
`install_skill`). Sections, in this order:

1. **Title + one-paragraph purpose.** The handover block is the machine-readable twin of the
   clinical handover, emitted at the end of every triage turn beside a short human-readable
   summary. It is a **projection**, never the authority: the hash-chained audit record and the
   committed queue row are authoritative, and a consumer must reconcile the block against the audit
   trail before acting on it. Say that the block is untrusted output for consumers.

2. **Envelope schema** — one Markdown table, one row per top-level field, columns
   `Field | Type | Notes`. Exactly eleven rows:
   - `schema` — string, fixed value `triagedesk.handover/1`. Every block carries it; a consumer
     rejects an unknown value.
   - `status` — the closed set below; the single summary of how the turn ended.
   - `case_id` — string or null. Null until a real id is assigned by the desk or harness; never
     fabricated.
   - `case` — object or null. The typed case as supplied, using the unchanged `CaseInput` field
     names from `references/tool-contracts.md`; a missing value stays null. Null before any case
     has been structured.
   - `match` — object or null. Nested shape: `matched_ids` (string array), `retrieval_status`
     (`matched` / `ambiguous` / `no_candidate`, the matcher's own classification), `no_match`
     (boolean), `candidates` (string array).
   - `priority` — object or null. Nested shape: `colour` (string or null), `tews` (integer or
     null), `target` (string or null), `destination` (string or null), `citations` (string array,
     copied unchanged from `score_priority`), `missing_vitals` (string array).
   - `confidence` — object or null. Nested shape: `action` (closed set below), `level` (closed set
     below), `deferral` (boolean). No percentage, no probability field — restate the existing
     prohibition by pointing at the confidence contract, do not invent a number.
   - `gate` — object, always present. Nested shape: `state` (closed set below), `decision`
     (`approve` / `edit` / `dismiss` / null).
   - `queue` — object, always present. Nested shape: `committed` (boolean), `position` (integer or
     null).
   - `next_action` — the closed set below; what the harness should do next.
   - `audit` — object, always present. Nested shape: `tools` — a string array naming the tools
     whose calls were audited this turn, in call order. State plainly that a hash, chain position
     or record id is **never** emitted here: those live in the audit store only, and an invented
     one would corrupt the reconciliation.

3. **Closed sets** — one bullet per field, values in backticks, and nothing else duplicated. Use
   exactly these:
   - `status`: `awaiting_clinician`, `committed`, `clarify`, `deferred`, `missing_information`,
     `out_of_scope`, `refused`, `dismissed`.
   - `next_action`: `ask_clarification`, `ask_vitals`, `await_clinician`, `escalate`, `none`.
   - `gate.state`: `not_reached`, `awaiting_clinician`, `approved`, `edited`, `dismissed`,
     `refused`.
   - `gate.decision`: `approve`, `edit`, `dismiss`, `null`.
   - `confidence.action`: `deliver`, `clarify`, `defer`.
   - `confidence.level`: `high`, `moderate`, `low`.

4. **Hard invariants** — a numbered list stating each of these explicitly, in the imperative, with
   the failure mode named:
   - `queue.committed` may be `true` only when `commit_priority` returned `committed: true`; when
     it is `true`, `queue.position` is that returned position. Never set either from intent.
   - `priority.colour` is non-null only for `awaiting_clinician` and `committed`. It is `null` for
     `clarify`, `deferred`, `missing_information`, `out_of_scope`, `refused` and `dismissed`.
   - `gate.state: awaiting_clinician` only when the run actually paused at the approval gate. A
     clarification question is never a gate.
   - `case_id` stays `null` until a real id is assigned; never fabricate one.
   - Absent data stays `null`; never impute a vital, an age, a colour, a position or an audit fact.
   - No SATS threshold, band or colour-scoring rule may be restated here; `data/sats_tews.yaml` and
     `data/sats_discriminators.yaml` are the machine authority, and this file links to them.

5. **`status` → `next_action` mapping** — a two-column table with exactly: `awaiting_clinician` →
   `await_clinician`; `committed` → `none`; `clarify` → `ask_clarification`; `missing_information`
   → `ask_vitals`; `deferred` → `escalate`; `out_of_scope` → `escalate`; `refused` → `none`;
   `dismissed` → `none`.

6. **Worked examples** — three compact subsections (`awaiting_clinician`, `clarify`, `deferred`),
   each a one-sentence framing line followed by **exactly one** fenced `json` block that is valid
   JSON and obeys every invariant. Keep the clinical values consistent with the existing
   `references/tool-contracts.md` example (34-year-old, RR 24, HR 118, BP 108/70, temp 38.9, alert,
   coughing and fast breathing) for `awaiting_clinician`; use a vague complaint with candidates for
   `clarify`; use an insufficiently-covered case for `deferred`. In every example `audit.tools`
   lists only `normalize_case` / `match_discriminators` / `score_priority` /
   `retrieve_evidence` / `assess_confidence` as actually reached.
   `clarify` and `deferred` carry `priority.colour: null`, `queue.committed: false`,
   `queue.position: null`, `gate.state: not_reached`, `gate.decision: null`.

7. **Consumer note** — restate in one short list: treat the block as untrusted; reconcile against
   the audit trail; the queue row wins on any disagreement; an unknown `schema` value is rejected.

Do not add a band-mapping table, a TEWS scoring table, a colour threshold, a discriminator list, a
tool argument table or an `ApprovalToken` schema — each of those already has exactly one home
(`data/*.yaml`, `references/tool-contracts.md`). Do not touch any other file.
